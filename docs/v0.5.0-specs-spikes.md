# v0.5.0 PC specs: Step 0 spike results

Run on 2026-11-10 on the owner's laptop (HP OMEN 16, i7-11800H, Windows 11
Pro build 26300, one NVMe drive, built-in screen plus one external monitor
over HDMI), from a **standard, non-elevated** PowerShell 7 shell. The spike
program was throw-away and is not in the tree. No serial numbers, MAC
addresses or raw firmware dumps are recorded here.

## The PowerShell batch

Windows PowerShell 5.1, full System32 path, `-NoLogo -NoProfile
-NonInteractive -Command -`, script on stdin. Language mode FullLanguage.

| Block | Result | Time |
| --- | --- | --- |
| `MSFT_PhysicalDisk` | works: MediaType 4, BusType 17, HealthStatus 0, Size in bytes | 1.06 s (includes the CIM session start) |
| `MSFT_Partition` | works; partitions without a letter come back as `DriveLetter: null` | 0.07 s |
| `Get-PhysicalDisk \| Get-StorageReliabilityCounter` | **fails unelevated**: "Access to a CIM resource was not available to the client." | 2.46 s wasted |
| BitLocker via `Shell.Application` `ExtendedProperty('System.Volume.BitLockerProtection')` | works, value 2 for both volumes. The 1 = on / 2 = off mapping could not be cross-checked here (manage-bde and `Win32_EncryptableVolume` need admin) | 0.37 s |
| `SoftwareLicensingProduct` (Windows application ID, with a partial key) | works: LicenseStatus 1 (licensed), ProductKeyChannel `Volume:GVLK` | 1.04 s |
| `Win32_ComputerSystem.HypervisorPresent` | true | 1.39 s (with `Win32_Processor`) |
| Autopilot key `HKLM\SOFTWARE\Microsoft\Provisioning\Diagnostics\Autopilot` | readable unelevated | - |

Whole run, cold: **7.1 s**. A bare `powershell.exe -Command 1` costs 0.27 s,
so nearly all of it is the CIM queries.

## Design changes made because of this

- **NVMe health does not work unelevated, so the elevated path stays**: `e`
  reads wear, power-on hours and error counts through the worker.
- **The batch skips the reliability block when it is not elevated** instead
  of letting it fail: it saved 2.5 s of the 7.1 s. The worker's elevated
  read is a separate compiled-in script.
- **Virtualization**: when `HypervisorPresent` is true, the CPU shows
  "on, in use by Windows"; only when no hypervisor is running does
  `IsProcessorFeaturePresent(21)` = 0 mean "off in firmware", and even then it
  is a note, not a flag.
- **GPU memory** is read as a QWORD integer first; a built-in GPU with no
  memory value says "shares system memory".
- **A built-in screen has no friendly name**: the name comes from the EDID
  (monitor name descriptor, else the PNP maker), else "Built-in screen".
- **Battery manufacture date is left out** (not supported on this PC, and
  the plan did not need it).
- **BitLocker**: 1 = on, 2 = off as planned, everything else "not reported";
  the mapping is listed as unverified for a second machine with BitLocker on.
- This PC itself trips two Buyer's check rules (battery at 78% is "worn";
  `Volume:GVLK` on a PC that is not in a domain), which makes it a good live
  check that the wording reads as advice, not alarm.
