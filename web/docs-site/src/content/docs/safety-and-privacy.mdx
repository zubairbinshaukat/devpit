Devpit deletes files and switches the accounts your tools use, so the rules are strict.
They are not settings and not advice.
The code enforces them, and a test pins each one.
Where a rule is decided but its test is still to come, this page says so.

## How deleting is protected

1. **You see a preview first.** Nothing is deleted before you have seen the list and the sizes.
2. **You must confirm.** Deleting only starts after you answer a question.
3. **The default answer is No.** Pressing <kbd>Enter</kbd> on a fresh question answers No. There is no way to build a dialog that starts on Yes.
4. **Careful items need a typed word.** You must type `DELETE` first. Pressing <kbd>y</kbd> is not enough.
5. **You are told how to get it back.** Every confirmation says how, for example run `npm install`.

### What is never pre-ticked

- Careful items.
- Projects you touched in the last 7 days.
- Folders Devpit could not fully verify.
- Cloud placeholder files (OneDrive, Dropbox). Devpit skips them and never downloads them.

### What Devpit checks before it deletes

- **The marker file.** A folder only counts as junk when its marker sits beside it: `package.json` for `node_modules`, `Cargo.toml` for `target`, a `.csproj` or `.sln` for `bin` and `obj`. Devpit checks again right before it deletes.
- **Links are never followed.** Junctions, symlinks and other reparse points are treated as dead ends. Following them is the bug that made other cleaners delete real source code.
- **Places that are always refused:** drive roots, anything inside the Windows folder, network paths, and every folder on your never-touch list.
- **Devpit's own program file** is always refused.
- **Current app versions** are never removed. For Scoop, Devpit leaves the version that `current` points to, and never touches `persist`.
- **Docker volumes** are never touched. Devpit does not run any Docker command that includes volumes, in any spelling.

### How deleting works

- **Safe items** are first renamed to a temporary name in the same folder. The rename is instant. It shows straight away that the space is freed, and it makes a crash harmless: you can never be left with a half-emptied folder that looks like a working one. A small marker file inside says which folder it was. Devpit finishes the removal later, from **Resume interrupted deletes**, and only for folders with that marker.
- **Review and Careful items** go to the **Recycle Bin**, so you can restore them.

### Stopping is safe

Press <kbd>Esc</kbd> during a delete.
Devpit finishes the item it is on and shows what was done.
Finished deletions stay done.
Nothing is left half removed.

### Nothing fails quietly

A locked folder, a folder you cannot read, a cancelled scan: each one is counted, named and explained on the summary, with what to do about it.
For example: "Couldn't delete api\node_modules — it's open in Code.exe. Close it and press R to retry."

## Other protections

- **Processes.** Devpit never stops PID 0 or 4, Windows services, or other programs in `C:\Windows\System32`. The shells `cmd`, PowerShell and `conhost` are the one exception, because dev tools start them all the time. See [Fix stuck ports and apps](/docs/features/fix-stuck-ports).
- **SSH keys.** An existing key is never overwritten. A key Devpit makes for a GitHub account gets its own file name, and Devpit stops if a file is already there. See [Git and GitHub accounts](/docs/features/accounts-git-and-github#generate-an-ssh-key).
- **Admin rights.** The app you type into never runs as administrator. Jobs that need it, such as Chocolatey updates, run in a separate small helper that asks Windows for permission once. The helper only accepts a short list of jobs, and only deletes inside a short list of Windows temp folders.
- **Settings file.** A damaged file is renamed and kept, never silently thrown away. A file from a newer Devpit is refused, not half applied. Saving is done in a way that never leaves a half-written file.

## Accounts

[Accounts](/docs/features/accounts) changes which account Claude Code, Git, GitHub and other tools use in a folder.
These rules apply to it.

### No tokens

- **Devpit stores no token.** Each tool keeps its own login where it always does. Devpit's rules file, `%APPDATA%\devpit\accounts.toml`, holds account names, emails and folder paths only.
- **No token is shown, copied, logged or put in `--json` output.** Who is signed in is read without the token, and everything Devpit shows or logs is checked for anything that looks like a secret. A test plants a fake token in fake tools and checks it never comes out.
- **The one token Devpit handles** is a GitHub account's, which it asks `gh` for when a `gh` or `git` process starts. It goes only to that process, in memory, and is never written anywhere. If anything goes wrong, `gh` starts untouched with one warning.
- **No command that prints or moves a token** is ever run: never `firebase login:list --json`, never `gh … --show-token`, never `gh auth switch`.
- **Login files are never read, copied or linked:** Claude Code's `.credentials.json` and Supabase's `access-token`. Only whether they exist is checked. Claude Code's `.claude.json` is never copied or linked either; only its MCP server entries are read, when you choose to bring MCP servers over.

### Every change can be checked and undone

- **Every change has a preview, and the default answer is No.** What is applied is exactly what you saw: if anything changed in between, Devpit stops.
- **Undo is exact.** Devpit records each change before it makes it, with what was there before. Undo puts it back. If a file Devpit wrote was changed by hand since, undo stops and changes nothing.
- **A crash never leaves a change half made.** A change that was not finished is put back at the next start.
- **An account folder that holds a sign-in is never deleted** by an undo, and a cancelled sign-in leaves nothing behind.
- **Nothing you type can add lines to Git's config.** A name, email or path with a line break is refused.
- **Without a terminal, nothing changes without `--yes`.** A script or an AI agent gets exit code 3 and the message "This would change … Re-run with --yes after the user agrees." Variables such as `CI` or `CLAUDECODE` never stand in for a person.

### What it touches, and what it leaves alone

- **Login and account folders can never be selected in Free Up Disk Space:** `.claude`, `.ssh`, `.devpit`, `.claude-switch`, and the `gh`, Vercel, Wrangler, Supabase and Convex login folders. Account folders Devpit makes live inside `.devpit`.
- **`devpit accounts cleanup` removes only what Devpit added:** folder rules, shims and their PATH entry, its Git files and include block, the Wrangler bindings it made and its agent skill. Never an account folder or a sign-in.
- **Sharing a Claude Code setup never overwrites anything** in the other account: same-named items are kept beside it, renamed, or moved to a backup folder. Links are never followed when removing.
- **Uninstalling never breaks an account.** Shared links point at your own `.claude` folder, and `devpit accounts cleanup --copy-links` turns them into copies.
- **Careful items** (MCP servers, which may hold API keys) are never ticked for you and are only copied on the Careful path. That they ask twice on screen is decided, but the screen's test is still to come.
- **Arguments reach a tool exactly, or not at all.** A shim never passes your arguments through `cmd.exe` in a way that could change them: npm tools run as `node.exe` directly, and other batch files only get plain arguments.
- **A broken Devpit never blocks a tool.** If the shim cannot work out the account, it starts the real tool untouched with one warning line.
- **Claude Code's idle accounts are not asked who they are** unless you agree, because on some versions that check can sign an idle account out (Claude Code issue [#95822](https://github.com/anthropics/claude-code/issues/95822)).

### No network of its own

Accounts has no network code.
The only connections are each tool's own sign-in and "who am I" check, which the tool makes itself.

## What Devpit sends

Short version: **usage stats are off until you turn them on.**

Everything else runs on your PC: the scan, the sizes, the deleting, the port list and your settings.
Devpit reads and writes these places, and nothing in them is uploaded:

| What | Where |
| --- | --- |
| Settings | `%APPDATA%\devpit\config.toml` |
| Account rules and the undo history | `%APPDATA%\devpit\accounts.toml`, `%APPDATA%\devpit\accounts-journal.jsonl` |
| Account folders Devpit made | `%USERPROFILE%\.devpit\accounts\` |
| Git rule files | `%USERPROFILE%\.devpit\git\` |
| Caches and logs | `%LOCALAPPDATA%\devpit\` |

### Usage stats (off by default)

On first run Devpit asks, with the answer already on No:

> Help show how much space Devpit saves? Only totals are sent — no file names or paths.

You can change your mind in **Settings**, then **Usage stats**.

If you turn it on, Devpit sends **one small report after a clean-up that removed something**. It is sent in the background to `https://devpit.zubyr.dev/api/report`. This is the whole report:

| Field | What it holds |
| --- | --- |
| `v` | The version of the report format (1) |
| `installId` | A random ID made on your PC. It is not made from your machine, user or network |
| `version` | The Devpit version, for example `0.2.0` |
| `os` | The operating system name, `windows` |
| `osVersion` | The Windows version number, for example `10.0.26100` |
| `freedBytes` | How many bytes were freed |
| `items` | How many items were removed |
| `types` | How many items of each kind were removed, by the short name of the rule that found them, for example `node_modules`. A name that is not a short plain name is dropped, not sent. At most 32 kinds |

**What is never sent:**

- File, folder or project names
- Any path
- Your user name, machine name or domain
- The contents of any file
- The apps or tools you have installed
- Anything at all when a scan finds nothing, or when you cancel

**How it behaves.** A report never slows you down. If you are offline or the server is slow, it is dropped quietly. It is not retried and not saved to disk. The server rejects impossible numbers. It keeps a hashed form of your IP address for at most one hour, only to limit how many reports one connection can send.

The totals are shown on the Devpit website as public counters: space freed, items by type and how many people use it.

### Turn stats off for good

Any one of these:

- Leave **Usage stats** off in Settings.
- Set `DEVPIT_NO_TELEMETRY=1` in your environment.
- Set `DO_NOT_TRACK=1` in your environment.

The two variables always win, even if the setting is on.
Devpit never asks in a run without a screen, and never turns stats on by itself.

```powershell
# for this terminal only
$env:DEVPIT_NO_TELEMETRY = "1"

# for your user account, from now on
[Environment]::SetEnvironmentVariable("DEVPIT_NO_TELEMETRY", "1", "User")
```

### Every other connection Devpit makes

These are not usage stats. Each one happens only for the reason given.

| When | Where to | What it is for |
| --- | --- | --- |
| Once a day, if the update check is on | `api.github.com` (public releases of Devpit) | To see if a newer version exists. Nothing but the web request is sent. The answer is cached on your PC. Turn it off in Settings or with `DEVPIT_NO_UPDATE_CHECK=1`. A build made from source never checks |
| You open **My IP addresses** | `api.ipify.org`, then `ifconfig.me` | To show your public IP address |
| You install the icon font | `github.com` (a fixed Nerd Fonts release) | To download the icon font. The file is checked against a fixed SHA256 before it is used |
| You run the installer or update | `github.com` | To download the release and its checksums |
| You use Install or Update | The sources of Scoop, winget, Chocolatey or npm | These tools contact their own servers. Devpit only runs their commands |
| You ping a host | The host you typed | That is what ping does |
| You add, check or use an account | That tool's own servers | The tool's own sign-in and "who am I" check, run by the tool itself (for example `gh api user` or `vercel whoami`) |

Devpit never downloads or replaces itself.
When a newer version exists it only tells you the command to run.

## Check what you download

- The install script is short and readable at [`devpit.zubyr.dev/install`](/install).
- It checks the SHA256 of the zip against the `checksums.txt` that comes with the release.
- Releases are built on GitHub Actions and carry a build attestation and a software bill of materials.
- Devpit is **not code-signed yet**, so Windows SmartScreen may warn about an unknown publisher. Devpit is never packed with UPX, because packed programs trip antivirus scanners.

To check a zip yourself, see [Getting started](/docs/getting-started#check-your-download-optional).
