**0x8A150101** means winget could not upgrade the app because it is running. Winget's own message is: "Application is currently running. Exit the application then try again."

## What it means

Winget has a list of return codes. This one is `APPINSTALLER_CLI_ERROR_INSTALL_PACKAGE_IN_USE`. The installer wanted to replace program files that are in use. Windows does not let a running program's files be replaced, so the upgrade stops and nothing is changed.

Two close cousins from the same table:

- `0x8A150103`: "One or more file is being used. Exit the application then try again."
- `0x8A150111`: "Application is currently in use by another application."

## Why it happens

- The app is open, or it is still running in the background or in the system tray after you closed its window.
- A helper process of the app is running.
- Another program has one of its files open.

## How Devpit fixes or avoids it

In [Update Everything](/docs/features/update-everything), Devpit reads the exit code of each winget step. For 0x8A150101, 0x8A150103 and 0x8A150111 the row says **in use, close it and retry** instead of showing a raw code. Scoop's "still running" message and npm's `EBUSY` are read the same way.

When an app has to be closed first, the row also names it, for example "close Contoso App and retry".
You can also press <kbd>s</kbd> twice to skip the app that is updating right now. The summary says how to retry it later.

## The manual fix

1. Save your work, then close the app. Also check the system tray (the small arrow near the clock) and quit it there.
2. If it will not go away, find it in Task Manager. Or end it by name in a terminal. `/im` is the program's file name and `/f` forces it:

```text
taskkill /im appname.exe /f
```

3. Run the upgrade again. `--id` picks the package and `-e` is an exact match:

```powershell
winget upgrade --id Publisher.PackageName -e
```

4. To read what winget itself says about any code, ask it:

```powershell
winget error 0x8A150101
```
