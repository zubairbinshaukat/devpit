Devpit shares skills, agents and commands between Claude Code accounts with **junctions**: entries in the other account that point at folders in your main `%USERPROFILE%\.claude`.
A junction is **broken** when the folder it points at is gone.

## Why it happens

- **The skill was deleted or renamed in your main account.** The link in the other account still has the old name.
- **The main `.claude` folder moved**, for example into OneDrive. Links to it no longer resolve. OneDrive does not keep links, so Devpit does not make them there.
- **Another tool replaced the folder** with something else.

## How to fix it

1. Open **Accounts**, then **Claude Code**, and open the account that shows the broken item.
2. Choose **Bring your Claude Code setup over…**. The item list marks the link as **broken link**. Press <kbd>r</kbd> to repair it. Repairing only changes the link, never your files.
3. If the skill was renamed on purpose, share it again under its new name. If it was deleted, remove the broken link.

A link made by another tool is left alone and the row says so; fix that one with the tool that made it.

Do not delete a shared folder through the link in the other account with Explorer or `Remove-Item -Recurse`: that can delete the files in your main account too.
To stop sharing, use **Stop sharing** in Devpit: it copies the item first and removes only the link.
