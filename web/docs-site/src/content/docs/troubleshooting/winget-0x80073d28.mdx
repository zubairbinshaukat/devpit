**0x80073D28** with the text "The package installation failed because administrator privileges are required" means the upgrade needs administrator rights and winget ran without them.

## What it means

This is not one of winget's own `0x8A15....` codes, and it does not appear in winget's table of return codes. The message that goes with it is clear: administrator privileges are required.

Microsoft's WSL project has a public report with this exact text. There, `winget upgrade Microsoft.WSL` was run in a normal PowerShell window. Winget should ask for elevation (a UAC prompt), but the upgrade stopped early with 0x80073d28 instead.

## Why it happens

- The package's installer needs administrator rights, and your terminal is a normal one.
- Winget did not raise a UAC prompt, or the prompt was closed.
- Some apps, such as a desktop app that installs a background service, can only be updated as administrator. Windows documents this as `ERROR_PACKAGED_SERVICE_REQUIRES_ADMIN_PRIVILEGES`.

## How Devpit fixes or avoids it

[Update Everything](/docs/features/update-everything) runs your updates as a normal user. Devpit itself never runs as administrator.

When an app fails with `0x80073D28`, Devpit does not fail it on the spot.
The row says "needs admin rights, retrying at the end".
After the other apps are done, Devpit tries all of these apps again together, with one administrator prompt.

<Shot name="update-admin-retry" />

If you decline the prompt, or the retry fails, the summary shows the command to run yourself in an administrator terminal.
If an app has to be closed first, its row says so, for example "close Contoso App and retry".

## The manual fix

1. Close the app you want to update.
2. Open **Windows Terminal** or PowerShell as administrator: right-click it and choose **Run as administrator**.
3. List what can be upgraded:

```powershell
winget upgrade
```

4. Upgrade the package by its ID. `--id` selects the package and `-e` means an exact match:

```powershell
winget upgrade --id Publisher.PackageName -e
```

Replace `Publisher.PackageName` with the ID from the list.

5. If it says the application is running, see [winget 0x8A150101](/docs/troubleshooting/winget-0x8a150101).
